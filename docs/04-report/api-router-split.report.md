## 8. Lessons Learned

1. **Import scan은 Design 단계 필수 절차로 격상 가치**.
   `from api.X import Y` 형태로 모듈을 직접 import하는 테스트가 두 곳(`test_input_validation.py`, `test_sql_validation.py`) 있었고, 그중 한 곳은 Plan/Design에서 식별, 다른 한 곳은 Check 단계에서 pytest collection error로 늦게 발견. 다음 분해 사이클부터는 Design에 *"전체 import 그래프 grep" 체크리스트 항목*을 의무화.

2. **OpenAPI 스키마 byte-identical을 AC로 두면 라우터 분해 안전성을 정량적으로 보장**.
   `tags=`/`prefix=` 을 의도적으로 생략하여 외부 호환 0 변경을 달성. 추후 v2 API 도입 시에만 prefix 채택.

3. **`api/tools.py` → `api/tools/` 패키지화는 동명 충돌 위험이 가장 큼**.
   원본 모듈 삭제 + `__pycache__` 청소를 Design 단계 Step에 명시한 것이 효과적. 비슷한 패키지화 사이클이 또 있으면 동일 절차 차용 권장.

4. **gap-detector의 "Added Features(positive deviation)" 패턴**.
   Design에 없지만 테스트 호환 목적으로 추가한 re-export는 "regression이 아닌 개선"으로 분류되어 일치율을 깎지 않음. 다음 사이클부터도 동일한 분류 원칙을 적용.
